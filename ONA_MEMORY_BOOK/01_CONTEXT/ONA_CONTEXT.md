> 아래 순서대로 읽으면 ONA 프로젝트의 철학, 현재 위치를 확인하는 방법,
> 그리고 프로젝트 맥락을 복원하는 방법을 이해할 수 있다.

# 0. ONA Project Context Recovery

ONA 프로젝트는 특정 사람이나 특정 AI의 기억에 의존하지 않는다.

프로젝트의 철학,
결정 과정,
현재 상태,
성장 기록을 문서와 구조로 기록하여

새로운 사람이나 새로운 AI도
같은 출발점에서 프로젝트를 이해하고 이어갈 수 있도록 설계한다.

# 1. ONA란?

ONA는 사람과 AI가 함께 성장하는
Human-AI Collaborative Learning Project이다.

ONA는 단순한 프로그래밍 프로젝트가 아니다.

ONA는 다음을 기록하고 연결하는
지식 시스템이다.

- 학습 과정
- 아이디어
- 프로젝트 결정 과정
- 실패와 개선 과정
- 성장 기록

ONA의 목표:

> "사람과 AI가 함께 성장하고,
> 지식을 공유할 수 있는 구조를 만드는 것."

---

# 2. ONA Core Philosophy

## Context Recovery System

    사람(Human)

          ↘

        ONA Project

          ↗

          AI

ONA는 특정 AI의 기억에 의존하지 않는다.

AI가 바뀌어도,

사람이 바뀌어도,

시간이 지나도,

프로젝트의 맥락은 다시 복원될 수 있어야 한다.

---

## ONA 핵심 원칙

> "ONA는 AI가 기억하는 프로젝트가 아니라,
> 누구나 같은 맥락과 기억을 복원할 수 있도록 만드는 프로젝트이다."

ONA는 기억을 저장하는 것이 목적이 아니다.

ONA의 목표는:

**맥락(Context)을 복원할 수 있는 구조를 만드는 것**

이다.

---

# 3. ONA Handover System

ONA는 단순한 프로젝트 문서가 아니다.

ONA는 사람과 AI 사이의
프로젝트 인수인계 시스템이다.

기존의 대화와 결정 과정은:

ONA_MEMORY_BOOK

에 기록한다.

현재 프로젝트 상태는:

ONA_MEMORY_BOOK/ONA_STATUS.json

에서 관리한다.

프로젝트의 방향과 변화 이유는:

ONA_MEMORY_BOOK/ONA_PROJECT_CONTEXT.md

에서 관리한다.

이를 통해 새로운 사람이나 AI도
이전 프로젝트의 흐름을 이해하고
같은 방향에서 이어갈 수 있다.

# 5. Change Review Protocol

ONA 프로젝트를 변경할 때는
변경 내용에 맞는 위치에 기록한다.

---

## 코드 변경

위치:

GitHub Repository

예:

- Python 코드
- UI
- 설정 파일

---

## 현재 상태 변경

위치:

ONA_MEMORY_BOOK/ONA_STATUS.json

예:

- 기능 완료
- 새로운 개발 단계
- 다음 목표 변경

---

## 설계 이유 변경

위치:

ONA_MEMORY_BOOK/ONA_PROJECT_CONTEXT.md

예:

- 구조 변경 이유
- 새로운 방향 결정

ONA_MEMORY_BOOK/ONA_CORE_MEMORY.md
