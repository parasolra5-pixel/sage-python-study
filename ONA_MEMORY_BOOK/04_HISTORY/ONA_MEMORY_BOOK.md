# 0. ONA Memory Book의 의미

ONA Memory Book은 단순한 백업 파일이 아니다.

이 책은 세이지와 ONA가 함께 만든 **생각, 철학, 프로젝트, 성장의 기록**이다.

코드는 시간이 지나면 바뀔 수 있다.
프로그램도 새로운 형태로 발전할 수 있다.

하지만,

- 왜 시작했는지
- 어떤 고민 끝에 선택했는지
- 어떤 철학으로 만들었는지

이 기록은 앞으로 ONA 프로젝트가 방향을 잃지 않도록 하는 기준이 된다.

ONA Memory Book은 ONA 프로젝트의 **심장(Foundation)**이다.

### 2026-08-08 — Efficient-First Operating Principle

ONA 프로젝트를 작업할 때는 파일이나 구조를 하나씩 수동으로 처리하기 전에, 먼저 더 효율적이고 안전한 방법이 존재하는지 판단한다.

작업의 기본 흐름은 다음과 같다.

```text
문제 확인
↓
현재 구조 확인
↓
자동화 가능성 판단
↓
효율적인 방법 제안
↓
Preview / Dry Run
↓
Human Approval
↓
실행
↓
결과 검증
↓
필요 시 기록
```

특히 파일 이동, 이름 변경, 삭제와 같이 프로젝트 구조에 영향을 주는 작업은 자동화할 수 있더라도 AI가 임의로 실행하지 않는다.

AI는 먼저 가장 효율적인 방법을 제안하고,
사람은 그 방법과 결과를 확인한 후 최종 승인한다.

따라서 ONA의 운영 원칙은 다음과 같다.

> **"수동 작업보다 먼저 효율적인 방법을 찾는다.
> 자동화보다 먼저 안전성을 확인한다.
> 실행보다 먼저 사람의 승인을 받는다."**

이 원칙은 ONA가 단순히 작업을 수행하는 시스템이 아니라,
사람과 AI가 함께 판단하고 구조를 만들어가는 Human-AI Collaborative Knowledge System이라는 철학을 실제 작업 과정에서도 유지하기 위한 것이다.

---

### 2026-08-08 — Expandable Structure Principle

ONA의 구조를 설계할 때는 **현재의 요구를 작게 해결하면서도 미래의 확장을 막지 않는 구조**를 우선한다.

핵심 원칙은 다음과 같다.

> **"미래를 고려하되, 미래를 미리 구현하지 않는다."**

즉, 지금 필요한 기능을 위해 거대한 시스템을 미리 만들지 않는다. 대신 현재의 작은 구조가 이후 더 많은 지식, Topic, Category, 도구로 자연스럽게 확장될 수 있도록 설계한다.

기본 흐름:

```text
현재 문제
↓
작은 구조 설계
↓
실제 실행
↓
검증
↓
확장 가능성 확인
↓
필요할 때만 확장
```

예를 들어 Micro Example Knowledge System은 현재 `integer`, `float`, `operators`와 같은 작은 Topic에서 시작하지만, 이후 더 많은 Topic과 Category가 추가되더라도 기존 구조를 불필요하게 다시 설계하지 않아도 되도록 한다.

이를 위해 ONA AI는 작업할 때 다음 세 가지를 함께 판단한다.

1. **현재 사용성** — 지금 필요한 작업을 단순하고 안정적으로 수행할 수 있는가?
2. **확장 가능성** — 새로운 Topic, Category, 기능이 추가되어도 기존 구조가 자연스럽게 수용할 수 있는가?
3. **복잡성 관리** — 미래를 대비한다는 이유로 현재 필요하지 않은 시스템을 미리 만들고 있지는 않은가?

특히 특정 이름이나 특정 개수에 구조가 고정되는 하드코딩을 가능한 한 피하고, 현재의 작은 구현이 일반적인 구조로 확장될 수 있는지를 먼저 확인한다.

그러나 확장 가능성을 이유로 미리 거대한 시스템을 만드는 것은 피한다.

> **작게 만들고 → 실행하고 → 확인하고 → 필요할 때 확장한다.**

이 원칙은 ONA의 Micro Example System뿐 아니라 문서 구조, Loader, Generator, Knowledge Ecosystem 등 앞으로 만들어질 모든 ONA 구조에 적용한다.
